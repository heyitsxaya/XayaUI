# 2026-11-02 19:00 UTC - Notepad (floating reminder box)

Build 0.5.42 (pushed on top of origin 0.5.41; developed locally as 0.5.39). Fork instance: n/a. UNTESTED IN GAME. Syntax-checked and run once against stubbed WoW APIs (load, DB init, toggle, options table, reset, clear).

Request (Xaya): add a QoL feature called "Notepad": a floating box widget that takes typed text for reminders.

Built:
- New Notepad.lua (listed in XayaUI.toc after DataPanels.lua). Own code against Blizzard's frame API only.
- Movable (drag the title bar), resizable (bottom-right grip, 140x80 to 900x900), Lock button, x to close. Border is blue while unlocked, gray while locked.
- Multi-line EditBox in a scroll frame (mouse wheel, caret stays visible). Text saved on every change to CueRulesDB.notepad.text (8000-character cap). Open/closed state, position, and size are remembered.
- /xui notepad (alias /xui note) toggles it and puts the cursor in the box. Esc releases the keyboard.
- QoL UI Updates > Notepad options page: show, lock, hide in combat, release keyboard when combat starts (default on), font, size, backdrop opacity, strata, reset position and size, clear all text (with confirm).
- Default is closed, so nothing appears on screen until she opens it.

Files changed: Notepad.lua (new), XayaUI.toc, Core.lua (OnDBReady call, /xui notepad), Options.lua (ns.UI.Notepad, qol tree entry). Backups: *.pre-notepad.20261102.*.bak.

Risks to check in game:
1. EditBox keyboard capture: while the cursor is in the box, movement and ability keybinds do nothing. Esc or entering combat releases it (option).
2. Saved text lives in CueRulesDB (account-wide SavedVariables), not per character.
3. Plain-text only: no reminders that fire at a time or on an event yet. That would be a follow-up (timer or event triggers).

## Update 2026-11-02 (memos, toolbar, writeup)

Request (Xaya): store typed text as a notepad memo so accidentally deleted text can be retrieved; add a toolbar (customizable position, hover-over visibility toggle) with delete, add new note, duplicate note, etc.; write the feature up and add it to the addon documentation feature list.

Built (Notepad.lua rewritten; previous version backed up as Notepad.pre-memos.20261102.lua.bak):
- Multiple notes (memos) in CueRulesDB.notepad.notes; the earlier single-text save migrates into the first note.
- Per-note version history (default 20, range 5-50): saved after a 4 s typing pause, on focus loss, on note switch, on logout, and immediately before any single edit that removes 20+ characters.
- Trash for deleted notes (last 30). "Clear the current note" saves the old text as a version first.
- Hist button / options button opens a Restore list (earlier versions + deleted notes) with hover previews; restoring a version saves the current text first.
- Toolbar: New, Dup, Del, <, >, Hist. Options: show toolbar, position (Top/Bottom/Left/Right), only show on mouseover.
- Writeup: project doc claude/XAYAUI-NOTEPAD-2026-11-02.md (copy in "Claude outputs"). Feature list: README.md "What it does" now has a Notepad paragraph (backup README.pre-notepad.20261102.md.bak).

Checks: syntax OK; stub run covered migration, new, dup, prev/next, delete (to trash), clear (to history), restore popup toggle, all four toolbar positions, options functions. NOT covered: typing-triggered saves (OnTextChanged), hover reveal, real frame layout.

Risks to check in game:
1. Toolbar button widths at the minimum box size (about 200 px wide with the toolbar on top or bottom).
2. Hover reveal: does the toolbar fade in reliably when the mouse enters the box?
3. Restore list placement next to the box near screen edges (clamped to screen).
4. SavedVariables size growth with many long notes.
5. Edits are still on disk only after /reload or logout.

Process decisions: toolbar inside the box (not a separate floating frame) to keep one movable unit; history by idle + pre-deletion snapshot (a pure timer would miss a wipe within 4 s); trash capped at 30 and history capped per note to bound file size; default hover OFF so the toolbar is discoverable.
