# Combat engine loads as part of XayaUI: pulling main is enough (XayaUI 0.5.95 / engine 0.4.1, fork: main)
Logged 2026-11-03 ~02:30 UTC. GitHub issue: #311. Context: tester Insivius installs by pulling the main branch with GitHub Desktop into Interface\AddOns\XayaUI. The engine lived in a nested folder that WoW does not load (only top-level addon folders load), so a plain pull never ran the engine: no engine, no durations in combat.
Change: XayaUI.toc now lists the five engine files at the end, so XayaUI loads the engine itself. Each engine file starts with a load-once guard (ns.engineFiles): if the separate XayaUI_CombatEngine folder is also installed (as on Xaya's machine), its copy steps aside. Performance guard reads Blizzard_AuraContainer plus XayaUI_CombatEngine (the engine's own Lua is counted under XayaUI when XayaUI loads it). Off switch is /xuiengine auto off (disabling the separate addon entry no longer turns it off).
Verified offline: whole-toc bench loads all engine files with no errors, decisions identical to the previous build; aura_display_run includes a second-load check (same module, same slash command, no second hooks); layout_parity_run passes.
Unverified in game.
Files: XayaUI.toc, XayaUI_CombatEngine/*.lua (load guard), XayaUI_CombatEngine/AuraDisplay.lua (guard metric), XayaUI_CombatEngine/README.md, XayaUI_CombatEngine/XayaUI_CombatEngine.toc, USER-GUIDE.md, tests/aura_display_run.py, MANIFEST.md5.
