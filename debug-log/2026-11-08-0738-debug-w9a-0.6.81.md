## Choices her words leave open (built provisionally, listed for her; nothing else was decided)
- **G1 direction.** Boxes: left to right (top and bottom edges carry the gradient, the left edge is the first colour, the right edge the
  last). A line runs along its own length (the pane divider top to bottom). The value model has a `dir` ("V" = top to bottom) with no
  control yet. Alternative: around the box (a trail flowing round the edge).
- **G2 which windows.** The settings window and core's flat buttons (console, copy box, debug report). Not changed: the version pane
  (InfoPane.lua), the import window, Blizzard Reskin / Character / Chat windows (they keep the solid border colour), the dropdown boxes
  (Skin.lua `Flat(w.dropdown ...)`), the Esc menu button.
- **G3 the solid colour of a gradient.** Everything that asks for one solid colour (T.Col: every caller outside the painted elements,
  e.g. BlizzardSkins WinBorder, CharacterToolkit lines) gets the colour the token had before (cursor themes: the grey XUI default), not
  the gradient's first stop, so nothing outside her four elements changes look. The brief suggested the first stop; this keeps the
  "nothing else changes" side. Her pick.
- **G4 one Reverse per theme**, not per colour; it is part of the theme (saved and shared with it) and stays when another base theme is
  picked (like the font and size). Label "Reverse gradient direction", placed under the theme choice, outside Advanced.
- **G5 Advanced "gradient as a colour" draws a gradient only on borders**; any other colour set to the gradient (text, backgrounds)
  shows its solid colour (the option's help text says so). Which other elements should draw it: her pick. Class overrides: no gradient
  option (a class colour of your own is solid).
- **G6 the gradient used by the Advanced option is copied in when ticked** (so it travels in the share string); it does not follow later
  accent changes until ticked again.

## Scope (V4)
- Resolver: `T.Resolve` (new `T.curGrad`), `T.Grad(class, prop, scope)` next to `T.Col` (same order: class colour of your own >
  your gradient / false > your solid colour > the theme's gradient; scopes: own overrides, chosen theme, parent, global; scope answers
  cached in `scopeCache`, dropped on OnResolve). `T.Col` unchanged (byte-for-byte the same answers).
- Storage: `CueRulesDB.theme.grads[token]` (gradient or false), `CueRulesDB.theme.gradRev`, saved themes the same, scopes
  `scopes[id].grads`. Writers: SetTokenGradient, SetGradReverse, SetToken / ResetToken (drop your gradient for that token), SetBase /
  ClearCustom / ResetAll, Load, ApplyTheme (import), SetScopeTokenGradient; DB() treats own gradients as Custom like own colours.
  Readers: Snapshot (Save, Export, UnsavedColors), CheckTheme (import cleaning: 2-8 stops, clamped, known tokens only, `false` kept,
  `gradRev` only when true), T.SavedGrads / T.BaseGrads, the Themes profile part (it carries CueRulesDB.theme as before).
- Painters: Skin.lua Flat (5th arg) at its 7 themed call sites (FlatInner, LayTabRow, SkinTabGroup, bulk bar, xuiTab, SkinButton,
  SkinInline box), SkinFrame (window backdrop), PaneDivider, SkinInline top line, FlatHide / release paths, HideRegions (skips our
  pieces, `xuiOwn`); Core.lua FlatBox / PaintFlatButton / FlatHideArt / skin-off path. Not changed: Flat row fills (no outline),
  `Flat(w.dropdown ...)`, every other T.Col caller (listed above).
- Theme page: `gradRev` and `gradTokens` nodes; the Advanced toggle's desc names the new option.

## Game API (V2), docs/reference/api/widgets.md, Texture (12.1.5)
- `SetGradient(orientation: Orientation, minColor: colorRGBA (ColorMixin), maxColor: colorRGBA (ColorMixin)` · SecretArguments=AllowedWhenUntainted · SimpleTextureBaseAPI
- `SetColorTexture(colorR: number, colorG: number, colorB: number, a: SingleColorValue?)` · ChecksForbiddenAspects=[{'Argument': 'self', 'Aspect': 'ForbiddenAspect.SetTexture'}], SecretArguments=AllowedWhenTainted · SimpleTextureBaseAPI
- `SetVertexColor(colorR: number, colorG: number, colorB: number, a: SingleColorValue?)` · SecretArguments=AllowedWhenTainted, SecretArgumentsAddAspect=[SecretAspect.VertexColor, SecretAspect.Alpha] · SimpleRegionAPI
- `GetVertexColor()` → `colorR: number, colorG: number, colorB: number, colorA: number` · MayReturnNothing, SecretReturnsForAspect=[SecretAspect.VertexColor, SecretAspect.Alpha] · SimpleRegionAPI
- `CreateColor`: Blizzard's ColorMixin constructor (FrameXML; not in the generated docs). Blizzard calls it with SetGradient in
  Blizzard_NamePlates.lua (`self.Left:SetGradient("VERTICAL", CreateColor(r, g, b, a), CreateColor(r, g, b, 0))`) and
  Blizzard_PrivateAurasUI.lua (`border:SetGradient("VERTICAL", CreateColor(1, 1, .557), CreateColor(1, .792, .188))`) (GitHub code
  search of Gethe/wow-ui-source, 2026-11-08); XayaUI already does in GameMenuButton.lua and TreePaint.lua.
- Secrecy: our arguments are plain theme numbers on our own textures; "AllowedWhenUntainted" is met (no secret value is passed).
- INFERENCE (not documented): HORIZONTAL puts minColor at the left; VERTICAL puts minColor at the BOTTOM (the code passes the lower stop
  as min); SetVertexColor sets all four corners and clears a gradient, so a piece going back to solid gets SetVertexColor(1, 1, 1, 1)
  first; anchoring to a cleared (alpha 0) edge texture keeps its size. One SetGradient spans two colours, so n stops = n - 1 pieces.
  The B294 walkthrough reads back what was handed to SetGradient (kept on each piece) and GetVertexColor; she confirms the look (step 2).
- The stand-in (tests/harness/world.lua) now records SetGradient (orientation + both colours); SetVertexColor clears it; SetColorTexture
  keeps it (the cautious reading).

## Cost (V14)
No OnUpdate, ticker or event. Gradients are worked out once per T.Resolve (`T.curGrad`); scope answers cached. A frame drawing a gradient
of 3+ colours gets one OnSizeChanged hook (its pieces depend on its size); the relay is removed when it is solid again, and the hook
then returns at once (a hook cannot be removed: stays until /reload, the V14 limit). A solid theme creates no new texture, hook or table
(paint parity below). The skin pass now repaints the title bar's ? and collapse arrow on every pass (2 PaintFlatButton calls): before,
they took a theme change only when shown again (found by the new test: under Light mode they kept the Class colors border; a pre-existing
repaint gap, fixed because her "Buttons" includes them).
