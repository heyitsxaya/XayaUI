## Resolver changes (Theme.lua, Platform)
- `T.Bind(key, tbl, scope)`: a bound table follows a scope (Skin.lua / TreePaint.lua bind to "settings"); T.Resolve drops the scope
  cache first so scoped binds read fresh answers.
- **Fix to P1:** a scope's chosen theme is now complete: a colour the theme does not list is the XUI default (as when it is picked in
  Settings > Theme). Before, it fell through to the global theme (an element on Class colors under a global Light mode kept Light's
  window colour).
- New: `T.ScopeCol`, `T.ScopeTok` (a colour only when a scope decides it), `T.TokCol`, `T.ScopeOverrides`, `T.ScopeComesFrom`,
  `T.HasScopes`, `T.ResetAllScopes`, `T.SetScopeTokens`; RegisterScope keeps `page`, `own`, `rowOrder`.
- `T.ResetAll` (Settings > Theme "Reset everything") is unchanged: it leaves the scopes (C15 open, recommended "global only").
- Repaint on change: Blizzard Reskin now repaints live pages on a theme change (one OnResolve listener, only while a page is live,
  taken off when none is; before, windows took a theme change on their next show and the minimap, status bars and minimap buttons only
  after /reload). The Esc menu repaints while shown (listener only while its look is on). The Chat Panel's listener also repaints when
  its scope has data or was drawn last time.

## Folded-in overrides
- **Esc Menu**: at Reskin's settings-ready (before the first paint), if `gm.useColors` is true and the fold mark is absent, the six
  colours become the scope's palette colours: panel fill = windowBg, panel border = border, button fill = buttonBg, button border =
  buttonBorder, accent = accent, title = label (alpha 1; the opacities stay the page's sliders). Mark `themeFolded` in Reskin's own
  store (key added to Modules.lua SETTINGS_KEYS.reskin); with "Use my own colors" off nothing is written. The old keys stay untouched
  (P6 removes them). The menu now paints: a colour its scope decides, else its old theme look (button border, accent, fixed 0.04 / 0.07
  fills). The page's Colors group is replaced by the Theme row; "Reset Game Menu settings" also resets the scope (it reset the colours
  before).
- **Chat Panel**: nothing copied (C-W9b-2). The chat draws a colour its scope decides whatever "Use the XayaUI theme" says; otherwise as
  before. Its row says "this element" while the switch is off (its own Appearance colours, through the scope's `own`).

## Cost (V14)
A scope costs one table entry, made at file load by the module that owns the element; an addon that is off makes none. Paint calls with
no scope data take T.Col's first branch: one ScopeData lookup per chain step, cached per scope / class / prop until the next Resolve.
New listeners exist only while their element is live (Blizzard Reskin, Esc menu). The Theme page lives in the load-on-demand settings
addon.
