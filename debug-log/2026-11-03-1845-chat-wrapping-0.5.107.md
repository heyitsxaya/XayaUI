# Xaya: Chat Panel "chat wrapping isn't working properly" (XayaUI 0.5.107, fork: main)
Logged 2026-11-03 ~18:45 UTC. Xaya posted a Chat Panel screenshot: text runs past the pane's right edge, and a "[View Loot Rolls]" link is split across two lines.
Evidence from the screenshot (measured, inference): pane / text area right edge about 534 px, wrapped line reaches about 557 px; the width the text was wrapped at works out near 545-562 px against a text area of about 526 px, so the text was laid out roughly 20-35 px too wide. Saved chat settings: width 440, height 230, scroll bar hidden.
What the game's code does (Blizzard_SharedXML/ScrollingMessageFrame.lua, build 12.1.5.70688): RefreshLayout sets every line's width to frame:GetWidth() once; it runs again only after a size change the frame hears about (OnSizeChanged marks the layout dirty) or a font change. The Chat Panel gives the game's chat frame its size through two anchors on its text area, so a width the frame had before the move can stay in use. That is the leading hypothesis; it is NOT confirmed (no in-game measurement yet). Nothing in the game's chat XML reserves space for the hidden scroll bar that would explain 20-35 px.
Change: (1) C.WrapStatus / C.WrapOff measure the frame's width, the text area's width, the first line's width and the widest text. (2) C.Rewrap marks the frame's layout dirty and refreshes it; called 0.1 s after every re-anchor, when the text area changes size, and by the 0.3 s upkeep whenever a line's width differs from the frame's by more than 0.6 (at most once a second). (3) New command `/xui chat wrap` prints those numbers and the screen scale of both, then lays the text out again and prints the numbers after.
Verified offline: tests/chat_run.py (6 new checks: consistent widths left alone, stale line width detected, status numbers, Rewrap marks dirty and refreshes, throttled, no lines table is not an error); the whole chat_run / chatprobe_run suites pass.
Unverified in game: whether stale layout width is really the cause. If the wrapping is still wrong after this build, run `/xui chat wrap` and paste the output: line width equal to window width but text still too wide means the cause is elsewhere (font, scale or the text area itself), and the numbers say which.
Files: Chat/Frame.lua, Chat/Core.lua, tests/chat_run.py.
