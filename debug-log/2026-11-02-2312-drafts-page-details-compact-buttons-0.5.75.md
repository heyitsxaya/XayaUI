# Drafts page shows what each draft holds, with compact buttons; clearer unsaved-changes wording (build 0.5.75, fork: main)
Logged 2026-11-02-2312 UTC. GitHub issue: #289 (filed afterwards by the session that folded this build into main as 0.5.76; the build number in the title below is the local-only number).

Xaya, two messages with screenshots:
1. Drafts page: "condense these buttons so that more can fit into a single row. we want to show details about what the trigger, cue, and icon/sound is so that we can better understand what we're looking at in the draft viewer".
2. The yellow bar text ("Unsaved changes. They already apply, so you can test them. Press Save changes to keep them. If you close the window first, the changes are moved to Drafts and the rule goes back to its last saved version."): "this is not 'good' english".

Before: each draft was a box with only two wide buttons ("Put back in editor", "Delete draft"); a date line was meant to sit above them but did not show in her screenshot (cause not found; inference: the full-width description measured at height 0 in the skin's row layout).
Change (Drafts.lua, `ns.BuildDraftsPage`): per draft, row 1 = a date / kind / counts line (relative width 0.72) with two short buttons beside it (Restore 0.13, Delete 0.11, same relative-width pattern as Outcomes.lua); row 2 = the triggers; row 3 = the cues. Triggers: Cooldown and Aura with spell name, ID, and state; extra trigger rows by type plus their first spell or item. Cues: sound label, speech text, icon (own spell / item / file, or "from the first trigger" with the picture inline), texture file or atlas name, text; a named cue shows "name = ...". Up to four items per line, then "and N more". An older rule with no cues shows its own sound and display. A draft that cannot be read still gets its box and buttons. Read-only: nothing touches the live rules.
Wording (Drafts.lua `ns.DraftBarText`, used by the strip in Options.lua and the note on each rule tab): "You have unsaved changes. They are already active, so you can test them now. Select Save changes to keep them. If you close this window first, the changes are stored in Drafts and the rule returns to its last saved version." and "This rule has not been saved yet. It works while this window is open. Select Save changes to keep it. If you close this window first, the rule is stored in Drafts."
Tests: `tests/drafts_run.py` (14 checks, stand-in game functions). Syntax of Drafts.lua and Options.lua loads. NOT tested in game: whether the info line and the three rows draw, row spacing, whether the buttons line up with the first line. Other player-facing strings with similar wording were not changed (the Drafts intro text was reworded; the chat message when closing the window still says "kept in Drafts").
