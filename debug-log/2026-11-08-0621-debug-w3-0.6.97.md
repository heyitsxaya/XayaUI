## #478 collapsed window: title-bar buttons beside the title (built)
Reproduced (V3) in the stand-in window (real AceGUI / AceConfigDialog, tests/debug_w3_run.py): open, X right edge 1371; after the
collapse arrow the X sat at 1023 (just right of the title, centre 960) and the arrow at 919, the ? at 893 (her screenshot).
Cause: `SetCollapsed` (Options.lua) re-anchored the X to `titlebg` RIGHT +36 and the arrow to `titlebg` LEFT -36 (the ? follows the
arrow). The comment quoted no ruling of hers. Fix: one `AnchorTitleButtons` used in both states (X TOPRIGHT -6,-4, arrow -32,-4).
Second cause found while testing the walkthrough: a redraw while collapsed (the first-open Notify, a walkthrough step, any rule change)
re-applies AceGUI's stored window width (AceGUIContainer-Frame.lua ApplyStatus, status.width 780) after Skin.lua `ns.UpdateMinWidth`
had widened the frame to its minimum (834 here); collapsed, UpdateMinWidth returned at once, so the window narrowed by 54 px and the
right-anchored buttons moved 27 px left. Fix: SetCollapsed notes the window's width (`xuiChrome.openWidth`) and UpdateMinWidth, while
collapsed, keeps the window at least that wide. (A first try that wrote the widened width into AceGUI's status table instead made
tests/picker_rows_layout_run.py fail 2 checks, a row's text 16 px past its row: dropped.)
Tests (fail on the old code): debug_w3_run.py "#478 collapsed: the X / arrow / ? stays where it is", "none of them next to the title",
"collapsed, after a redraw" (this one also fails with the width keep removed: negative control run), "expanded again: the same places".
V4 scope (`git grep SetCollapsed / xuiChrome`): Options.lua only (SetCollapsed, EnsureChrome, OnRelease, the 0.25 s driver);
Skin.lua reads `xuiChrome.collapsed` (SkinFrame: title bar and drag strip hidden; UpdateMinWidth returns early). XayaUI_Chat's
`C.SetCollapsed` is another feature (chat panel), not touched.

  child Button with `obj == widget` and text (`FrameCloseButton`). The Ace library file is not edited.
