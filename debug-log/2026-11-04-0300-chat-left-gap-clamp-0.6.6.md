# #346 left gap: the game's clamp-to-screen margin pushed the chat window right of the text area (XayaUI_Chat 0.6.5 -> 0.6.6, fork: claude/exciting-hypatia-huaqbv)
Logged 2026-11-04 ~03:00 UTC. GitHub issue: #346. Xaya: "chat is still broken" (screenshot: chat text starts about 30 px right of the tab row and the input line), then the output of /xui chat indent and /xui chat wrap.
Evidence (her /xui chat indent): "window left 32.0, text area left 6.0 (setting: 6 px), text area to window: -26.0 px"; lines 6 to 9 "box left 0.0 px from the window edge"; timestamps off ("%I:%M " is the format setting, lines carry no timestamp). Wrap: window 414.0 = text area 414.0, no overflow, indent on (0.6.5 indent works; seen in her screenshot). So the gap is not inside the window: the whole window sits 26 units right of the text area it is anchored to (TOPLEFT and BOTTOMRIGHT to the text area, Frame.lua C.Anchor). Text area left = 6.0 = the 6 px inset, so the Chat Panel sits at the screen's left edge.
Cause (Blizzard source, wow-ui-source live 12.1.5.70783, read this session): FloatingChatFrameTemplate is clampedToScreen="true" (Blizzard_ChatFrameBase/Mainline/FloatingChatFrame.xml:425), and Edit Mode gives its systems clamp margins from their selection box (Blizzard_EditMode/Shared/EditModeSystemTemplates.lua:174-186, EditModeSystemMixin:UpdateClampOffsets -> SetClampRectInsets; the main chat window is an Edit Mode system, EditModeChatFrameSystemMixin). A negative left margin keeps the window that far from the screen edge, which overrides the anchor. That the main chat window's selection box reaches about 32 px left of the window (around Blizzard's button strip) is an INFERENCE from the 32.0 reading; the file that anchors it was not found in the source mirror. Why the 0.6.5 session could not reproduce the gap: its screenshots likely had the chat away from the screen edge (inference).
Change: while the Chat Panel is on, every chat window it places is not clamped to the screen (C.Unclamp in C.Anchor; the pane is what the player places). C.Glued reports "not glued" when the game clamps the main window again, so the upkeep re-anchors and unclamps it. Turning the Chat Panel off restores each window's own clamp value (C.Teardown). /xui chat indent now prints "clamped to the screen" and the clamp margins.
Checks: tests/chat_run.py 5 new checks (unclamped while on, re-clamp detected, re-anchor unclamps, off restores, report prints margins); negative control without the unclamp: 3 of them fail. All tests/*_run.py pass.
Needed from Xaya: /reload with the chat at the screen's left edge; the text should start where the tab row starts. If not, send /xui chat indent again (it now shows the clamp values).
