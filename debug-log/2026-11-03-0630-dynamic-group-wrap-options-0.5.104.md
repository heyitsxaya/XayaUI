# Xaya: dynamic groups should have row / column wrap options (XayaUI 0.5.104, fork: main)
Logged 2026-11-03 ~06:30 UTC. GitHub issue: #318 (new). Reported against build 0.5.103 (screenshot: "Externals" dynamic group, 11 icons in one row, no way to wrap them).
Cause: a dynamic group wrapped only when its Container width / height was set and the items overflowed it, and there was no way to say "N per row" or to put extra rows on the other side.
Change (Group tab > Group Type & Container, dynamic groups only): **Items per row / column** (0 = no limit; cWrapN) and **New rows go / New columns go** (below or above the first row; right or left of the first column; cWrapRev). The container size still wraps too; whichever limit is hit first wraps. Implemented in XayaUI's layout (Visual.lua LayoutDynamic, DynamicFirstOffset) and in the combat engine (AuraDisplay.lua FlowFor / WrapLimit, so the engine's icons wrap and grow the same way). Saved groups are unaffected (new keys default to the old behaviour).
Limits (flagged): the engine uses the first display's size for every icon, so by-count wrapping matches XayaUI exactly only for same-size displays; centred growth is drawn by XayaUI (not the engine) and wraps by the same rule.
Verified offline: tests/layout_parity_run.py (4 new first-icon parity cases + 6 new XayaUI wrap-position cases, all pass), tests/aura_display_run.py (9 new flow-setting checks, all pass), other suites pass. NOT verified in game: Blizzard's container honoring the maximum line size with a bottom/right anchor when rows go up/left.
