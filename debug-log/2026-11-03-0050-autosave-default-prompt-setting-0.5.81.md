# Autosave by default; "Prompt for saving and enable drafts" option (XayaUI 0.5.81, fork: main, issue #295)
Logged 2026-11-03 00:50 UTC.

Xaya: "by default, let's have auras save when you make changes. make it so that you can toggle this behavior as an option for 'prompt for saving and enable drafts'" (screenshot of the yellow unsaved-changes bar). Change: new setting CueRulesDB.ui.promptSave, default off, in Settings > UI Options > Saving. Off: ns.DraftDirty is always false (no bar), ns.DraftNew stores nothing, ns.DraftsOnClose keeps everything (no revert, no draft), the Drafts sub-tab is hidden unless old drafts exist. On: unchanged behavior. ns.DraftsApplySetting re-takes every rule's saved version at the moment of the switch. Edits were already live; "autosave" here means we stop reverting them on close. Undo is untouched. Existing drafts stay and can still be restored. Tests: tests/drafts_run.py (22 checks, 8 new). Not tested in game. Weak points: with the option off there is no way back to an earlier version except Undo, and the rule-edit "Discard" is gone; the Drafts tab hiding relies on AceConfig re-evaluating the hidden function when the option is toggled (a /reload fixes it if not).
