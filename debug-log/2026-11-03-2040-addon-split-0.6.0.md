# Xaya: one addon per feature area, built as one integrated release (XayaUI 0.6.0, fork: main; built on branch restructure-0.6.0)
Logged 2026-11-03 ~20:40 UTC. Requests (in order): split XayaUI so features can be switched on or off (#326); the map: XUI core (rule creation, combat aura tracking), XUI Chat, XUI QoL, XUI Bonus Features, XUI Blizzard Reskin, XUI Options (its own folder, like the big addon suites); one folder per addon in the repository; "the most logical siloing" over efficiency; no piecemeal patches, high first-pass confidence for two testers.

What changed
- Repository layout: XayaUI/ (core), XayaUI_Options/, XayaUI_Chat/, XayaUI_QoL/, XayaUI_Bonus/, XayaUI_Reskin/, XayaUI_Media/, XayaUI_GameDump/; shelved/ for the QoL Elements; tests, logs and documents at the root. Each addon folder is installed as-is into Interface\AddOns.
- Core keeps: rules, cues, conditions, actions, Combat/ (the former XayaUI_CombatEngine folder), sharing and backups (Share.lua), theme, console, minimap button, ESC-menu button, aura source lookup (now with the embedded-aura reader), Compat.lua, Modules.lua.
- XayaUI_Options (## LoadOnDemand: 1): the settings window, its skin, Addon Info, import window, drafts, and the rule editor parts split out of Triggers.lua / Outcomes.lua / Theme.lua (TriggersEditor.lua, OutcomesEditor.lua, ThemeEditor.lua; moved line for line, verified). Ace3 libraries moved here. Core opens it through Modules.lua (ns.LoadOptions / ToggleUI / EditRule / OpenSettingsPage); the game's Options > AddOns entry, the compartment click and /xuiskin live in core.
- Modules.lua: registrations (startup, /xui commands, minimap rows, settings pages), messages (ns.On / ns.Fire: CONFIG_CHANGED, LOG, THEME_CHANGED, EDITED), services (ns.Provide / ns.Service), and the settings-window bridge. No file reaches into another feature addon (checked by the harness).
- Data Blocks became XayaDataBlocks-1.0 (LibStub), carried by Chat and Bonus; it also owns the data types (moved from DataPanels.lua).
- Settings window: one tab per feature addon (Chat, QoL, Bonus Features); the Game Menu look stays under Settings > UI Options > Display.
- Sharing (Share.lua, was Profile.lua): one codec, a handler per kind (rules XUI1, theme XUITHEME1) with its own version check, never-export fields (runtime "_" keys and fold state), combat deferral for rule imports, and a clear message when text of the other kind is pasted. "Profile" retired: the tab is Import / Export, saved snapshots are Backups (same saved key, CueRulesDB.profiles, so an older XayaUI still sees them). No export-everything button; the whole-setup snapshot stays as the skeleton for Backup (#87).
- Compat.lua: twelve calls that depended on 12.1.5 deprecation fallbacks now use the current API first (separate issue).
- Harness (tests/harness): whole-addon test in Lua 5.1 (separate issue). Unit tests moved to Lua 5.1 too.

Verified offline (not in game): harness on all 33 combinations of the feature addons (fresh install), and the everything-on combination on Xaya's real saved settings (two sessions + two reloads each); 20/20 unit test runners; static checks (no deprecated-only names, no cross-addon reach, identical library copies).
Unverified in game: everything. QA-CHECKLIST.md lists what the testers check, with the expected result of every step.
Files: every addon file moved; new: XayaUI/Modules.lua, XayaUI/Compat.lua, XayaUI/Share.lua (renamed), XayaUI_Options/*Editor.lua, every addon's .toc, XayaUI_*/Libs/XayaDataBlocks-1.0, QA-CHECKLIST.md, tools/manifest.py, tests/harness/*, tests/lua51.py, tests/run_all.py.
