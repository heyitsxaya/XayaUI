# Options split: the rule editor and the rules tree out of Options.lua (Options 0.6.83; platform split phase P3)

Logged 2026-11-07 19:37 UTC. Branch `claude/lucid-mayer-pv4ytn`, on main bd03eb5. Plan: `docs/plans/PLATFORM-SPLIT-2026-11-07.md`
sections 7, 10 (P3), 11 (R8) and 15 order 4; Q1 answered as proposed (the rule module owns its editor; folder name waits on B2).
A pure code move: nothing a player sees changes, no saved data, no load timing (`XayaUI_Options` stays `## LoadOnDemand: 1`).
Versions: Options 0.6.83, Dev Assist 0.7.56 (walkthrough only). QA step H13; walkthroughs "options-split" (part 1) and
"options-split-reload" (part 2, after the /reload), `XayaUI_DevAssist/QAWalks-options-split.lua`.

## What was done
- `XayaUI_Options/Options.lua` 9,044 -> 1,650 lines. What is left is the window plumbing (plan section 7, Platform part): the top
  tabs, the feature tabs built from registered pages (`ns.OptionsApi.ModuleTabs`), grey-while-off and feature-row helpers, the tree
  cache (`Tree`), `Notify`, the small option builders (Col / Rng / Tog / Sel), Profiles (with the Recycle Bin sub-tab), Settings
  (UI Options, Theme, Debugging, minimap), page openers, the info pass, `BuildOptions` (now: Rules tab from the rule editor, then
  the rest as before), the cue memo, half-width inputs, Toggle and the window hooks, the debug console strip, the perf trace, the
  window chrome, the driver and what is published to core.
- New folder `XayaUI_Options/RuleEditor/`: the moved code, split by cohesion, plus the six existing rule-editor files.
  The extraction was generated from bd03eb5 by line ranges (no hand edits inside moved blocks); file-top imports were computed with a
  Lua tokenizer over the old file's top-level locals (every name a block used that another file now declares), checked for
  shadowing, forward references (none real) and names reassigned across files (one: `ruleClip`, solved by moving the paste block
  next to the only code that sets it, the right-click menu).
- Drafts.lua is rule-editor only (checked: its header and code hold the save / discard / undo of rules and the Drafts page; nothing
  else), so it moved too (the plan's ownership was an INFERENCE; now confirmed against the code).
- Settings > UI Options: the rule list rows on Display (header "Display Options", selection style, parent gradient, sidebar spell
  icons) and the whole Rule Creation tab moved to `RuleEditor/RuleSettings.lua`; Options.lua adds them through
  `ns.OptionsApi.RuleEditor.SettingsRows(Ui, Repaint)` (identical table, test A).
- Interface (the only ways between the two):
  - in: `ns.OptionsApi.Shared` = APP, AceConfigRegistry, AceConfigDialog, Tree, Notify, CoreS, PlatS, QolS, Col, Rng, Tog, Sel;
  - out: `ns.OptionsApi.RuleEditor` = BuildRulesTab() -> track, allQol, allBars; SettingsRows(Ui, Repaint) -> display rows, Rule
    Creation group; SelectedRule(); StatusText(rule);
  - inside the folder: `ns.OptionsApi.RuleEditorParts` (shared locals of its files);
  - besides these, both sides call namespace functions on `ns` as they did before (listed in the report; the namespace is shared by
    every XayaUI addon, so P4 can move the folder without changing them).
