# Formula capture walkthrough, fit tool and per-class observed data (GameDump 0.2.0 -> 0.3.0, Bonus 0.6.2 -> 0.6.3, fork: claude/exciting-hypatia-huaqbv)
Logged 2026-11-04 ~02:00 UTC. Request (Xaya): "create a walkthrough protocol so you can capture data from individual specs and talents based on gear (therefore number) changes. With enough data, make calculations and ship a spell_list_data database that isn't mined but directly observed from the game." Follow-ups: each database is per class, loaded on demand; only our own characters' spells matter, never other players'. Related: #339 (developer plugin), #325.
Change:
- XayaUI_GameDump/FormulaCapture.lua (new file, own slash /xuiformula; GameDump.lua untouched because the local copy has diverged, #339). A snapshot = stats (str/agi/sta/int, attack power, spell power per school, healing, versatility, haste, crit, mastery, max health, weapon damage and speed, equipped item level) + equipped item IDs + for every spellbook spell (this spec + general) and active talent: the description split into a template ("#" for each number) and its numbers, plus charges / recharge / rate and base cooldown. Grouped by loadout = class + spec + djb2 hash of the sorted active talent spell IDs. Auto mode snapshots 2 s after the last gear or talent change; duplicates (same stats) skipped; combat defers to PLAYER_REGEN_ENABLED; texts not yet loaded are requested and read again once. Saved in XayaUIGameDumpDB.formula. No names or realms.
- XayaUI_GameDump/FORMULA-CAPTURE-WALKTHROUGH.md: the in-game protocol (prep, 3+ power levels by removing gear, a versatility-only change with a ring or necklace, status check, save).
- tools/formula_fit.py: per loadout, spell and number, tries y = aX + b and y = (aX + b)(1 + vers) for each recorded stat (attack power first); keeps a fit only if it reproduces every observation within the game's rounding and has 3+ distinct X; reports the simplest coefficient that still fits (rounding skews least squares: 0.5196 -> 0.52); numbers that never moved are skipped; versatility reported as untested unless it changed at a fixed power; cooldowns tagged "scales with haste" when the rate equals 1 + haste at 2+ haste levels. Writes formula-report.md; --emit writes XayaUI_SpellData_<CLASS>/ (LoadOnDemand, depends on XayaUI_Bonus).
- XayaUI_Bonus/Tooltips.lua 1c: loads only the player's own class folder (C_AddOns.DoesAddOnExist / LoadAddOn) at login, spec change and after combat, out of combat; "Observed:" lines per number, preferring the row recorded with the player's own talent hash, otherwise "other talents". TooltipsUI.lua resets the talent match on talent / spec events only.
Checks: tests/formula_capture_run.py 19/19 end to end with a stand-in API whose numbers follow known formulas (2.77 and 0.52 × attack power × (1 + versatility)): capture, skip, combat defer, fit, constants excluded, haste-scaled recharge, LoadOnDemand toc, only own class loaded, tooltip line, other-talents flag, refusals (non-linear, untested versatility, two levels). tooltip_formulas_run 19/19, tooltips_run 47/47. Harness: XayaUI + Media + Bonus + GameDump passes; combinations with Options still fail on the earlier C_Texture stub gap.
Unverified in game (what the first real session will show): that GetSpellDescription numbers move with gear out of combat as assumed; whether rings / necklaces in 12.1.5 carry no primary stat (the walkthrough tells the player to check the tooltip); that C_SpellBook skill-line fields (offSpecID, itemIndexOffset, numSpellBookItems) read as named; whether some numbers follow weapon damage rather than attack power (the fit tries both, attack power first).
