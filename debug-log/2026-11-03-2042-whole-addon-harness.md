# Tooling: whole-addon harness in Lua 5.1 (tests/harness), unit tests on Lua 5.1 (XayaUI 0.6.0, fork: main)
Logged 2026-11-03 ~20:42 UTC. Xaya: "we keep patching things in piecemeal ... I need reasonably high confidence things will work on the first pass." Two gaps found: 11 of 21 unit test runners ran in Lua 5.5 (the game uses 5.1), and no test loaded the addon as a whole.
tests/harness/run.py: loads every addon folder the way the game does (toc order, dependencies, load on demand, saved variables after the files, ADDON_LOADED per addon) in every combination of the feature addons, plays a session (login, five seconds of frames, everyday events with real payloads, a fight, every /xui command, every minimap row, the settings window with every option read and written back), logs out, reloads twice, and fails on: Lua errors, widget methods or events the game does not have, unsaveable saved variables, settings that drift on reload, a settings window that does not build, deprecated-only names, a file reaching into another feature addon, differing copies of a shared library. Indexes of Blizzard's API documentation and UI code are built locally (build_api_index.py, build_framexml_index.py; not committed). --saved runs it on a real SavedVariables file (never committed).
tests/lua51.py + all *_run.py: Lua 5.1. tests/run_all.py: everything in one go.
Limits: a stand-in world, not the game: it proves the code loads, runs, and talks to the API names the game documents; it cannot show how anything looks or whether the live client returns what the documentation says.
