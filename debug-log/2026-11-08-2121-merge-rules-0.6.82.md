## 3. What was built
- Task 1, Delete N Selected (Sidebar.lua RowMenu): when the right-clicked rule is selected and more than one rule is selected (the
  "Link N Selected" condition, without its display requirement), "Delete N Selected" sits right under "Delete" and calls `ns.MultiDelete`,
  the selection bar's Delete (N): edit-locked rules left out with the count, the same question, one Recycle Bin item each, selection
  cleared, the list kept in place.
- Task 2 (TreeHelpers.lua `ns.GoHomeKeepScroll`): in Rules > Disabled a delete keeps the scroll position and selects DISABLED (the
  Disabled list's top row) instead of Enabled > Loaded; Enabled and Smart Categories unchanged. The comment now says which top row each
  list returns to.
- Task 3, Merge N Selected (new file RuleMerge.lua, listed after Sidebar.lua; menu entry after Link N Selected, before Move N Selected
  To): the right-clicked rule is kept. `M.Triggers` sorts each rule's triggers; `M.Apply` puts the others' present aura IDs into the kept
  rule's present trigger (its built-in Buff / Aura, else its first plain present row, else its free built-in, else a new row), missing ones
  likewise into one missing trigger, everything else as further rows (a built-in Cooldown becomes a "Cooldown (any spell)" row with all
  its fields; a present aura with "seconds left" becomes a Buff / Aura (another) row with its time, estimate switch and name), then
  `trigMode = "any"` when the rule has 2+ triggers. Only the others' triggers are read; their other settings go to the bin with them
  (`ns.RecycleRules`, one item each). The question lists the kept rule, every trigger it ends up with (aura triggers with each aura by
  name and ID; others as the Drafts page words them, `ns.DraftTriggerItems`), and the others going to the Recycle Bin by name. `M.Plan`
  checks everything on a copy first and again on Yes. Refused with a chat line naming the rule: a rule with 2+ triggers that is not
  "ANY trigger"; a cue / condition row; a built-in aura trigger with no aura ID; a kept rule with a built-in trigger in use but no state
  (with ANY it would always be true); more than 30 extra IDs on a merged aura trigger; more than 12 rows. Edit-locked rules are left out
  with the count. Sidebar.lua `ns.MultiSelected()` returns the selection in list order.
- One aura ID list rule: TreeHelpers.lua `ns.AuraIDList(mainID, ...)` (+ `ns.AURA_ALT_MAX = 30`), used by the four Trigger tab boxes
  (Editor.lua, TriggersEditor.lua) and by Merge instead of their copies; same results (numbers > 0, no repeats, never the main ID, 30 at
  most), and it also counts what did not fit (Merge refuses instead of dropping auras).
