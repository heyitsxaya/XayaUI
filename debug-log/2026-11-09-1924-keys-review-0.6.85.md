## 1. Game facts (V2)

  (read 2026-11-09): "command = GetBindingFromClick(keyOrButton)"; "keyOrButton: string - The mouse button or key that was pressed";
  returns "command: string - The command that keyOrButton is bound to. This is the same type that is passed to RunBinding." No notes:
  the return for an unbound key, how held modifiers count, and combat restrictions are not documented.

  - Blizzard_StaticPopup/StaticPopup.lua:791-798: `function StaticPopup_OnKeyDown(dialog, key) local bindingKey = GetBindingFromClick(key);
    if bindingKey == "TOGGLEGAMEMENU" then return StaticPopup_OnEscapeKeyDown(dialog); elseif bindingKey == "SCREENSHOT" then
    RunBinding("SCREENSHOT"); return; end`
  - Blizzard_FrameXML/Shared/CinematicFrame.lua:116-117: `function CinematicFrame_OnKeyDown(self, key) local keybind = GetBindingFromClick(key);`

## 3. Fix (V24 answers in each)
1. Text boxes let go when she is done.
   - Skin.lua `GuardBoxes` (run from the `ns.DecorateTrees` wrapper BEFORE the skin-off return, so it is not cosmetic): every AceGUI
     EditBox / MultiLineEditBox on the open settings page gets ns.KeyFocusGuard (within = the widget's frame; enterLetsGo for the one-line
     box). AddRest unguards it on release (ns.KeyFocusRelease), so a widget AceGUI hands to another addon is never touched.
     Enter lets go also when validation refuses the value (the reason shows; the text stays for a click back in): after Enter she is done
     typing, and a box that keeps the cursor keeps W/A/S/D and the screenshot key.
   - KeyCatch.lua: `opts.enterLetsGo` hooks Enter after the box's own script; hooks are installed once per box and act only while it is
     guarded (HookScript cannot be undone).
   - Calculator (decided by V24, as the brief asks): Enter works the sum out AND lets go. A line that keeps the cursor after Enter blocks
     movement keys while she plays; the answer stays in the line, so a click in it carries on from the answer, and the keypad needs no
     cursor. Opening the Calculator still puts the cursor in the line (she opened it to type).
   - Console command line: the same (Enter runs and lets go; a click types the next command).
   What she is doing: typing, then playing. Taken from her: the keyboard while a box has the cursor. Given back: Enter, Esc, a click
   elsewhere, the window closing, in and out of combat (ClearFocus is not restricted). Cost: one HookScript per box once; per click one
   pass over the guarded boxes (about 30 own boxes plus the open settings page's inputs); per decorate pass one walk of the page's widgets
   (the skin already walks them).
2. The screenshot key by its binding: KeyCatch reads `GetBindingFromClick(key)` once per key press while a XayaUI keyboard window is
   shown; a key bound to SCREENSHOT (or named PRINTSCREEN) never reaches the window's handler and is never held. Her screenshot on any
   key works, and a screenshot key that is also a key the window uses (she bound it to Delete) takes the picture and deletes nothing.
3. The settings window's Delete / Ctrl+Z / Ctrl+Y in combat (her row 59: kept): in combat the game does not let an addon keep a key back,
   so a used key would ALSO reach the game. KeyCatch now runs the window's handler in combat only for a key the game has no binding for
   (then the game does nothing with it, and the editor's action is the key's only effect). A bound key, or one whose binding cannot be
   read (unknown, never a guess), is the game's alone in combat: the editor does not act. Out of combat nothing changes (the editor uses
   the key and keeps it from the game). Failure mode: the editor does nothing on a bound key in a fight; the game is never blocked.
   Documented in Options.lua at the handler and in KeyCatch.lua's header.
- With other addons: AceGUI widgets are unguarded on release; KeyCatch's binding read is one call per key press while the window is shown.
- On /reload: nothing saved; hooks are made again on the first window or box. Feature off (V14): nothing new is created until a XayaUI
  window or box asks; the settings boxes are guarded only while the settings window builds pages.
- For the walkthrough: KeyCatch records the last key per window (key, combat, binding, used; one reused table) in ns.KeyCatchList and
  the last let-go (how: enter / escape / click / hide; time; window) in ns.KeyFocusLastLetGo.
