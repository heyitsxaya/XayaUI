# Duration not loading in combat; combat still sticky (build 0.5.86, fork: main)
Logged 2026-11-03-0100 UTC. GitHub issues: #306 (duration), #307 (sticky combat). Xaya: "duration still not loading but the aura is visible in my buff bar", "I did another perf run and have reloaded. combat still feels sticky and needs optimization".
Evidence: her saved variables (after reload) hold no perf numbers (they were printed to chat only), errorLog = {} and engineDisplay.groups = {} (the group is drawn by XayaUI, not the engine). Her group export: 34 cue rules with text enabled.
Found by reading Visual.lua: the in-combat duration path tested the aura instance id with ~= nil; the game forbids comparing a secret value, even with nil, so that test can fail exactly in combat. The old cooldown-widget path also depends on the game's own cooldown-number setting. Stack text had no source for auras found through the Cooldown Manager. Every visible display ran its full fade / wipe / text routine every rendered frame, and the curve caches built strings on every call.
Changes (unverified in game): instance id tested by truthiness; duration text drawn from the duration object's remaining time as our own text, cooldown widget as fallback; stack text from the game's display count when no readable stack number exists; per-frame effects capped at ~30/s; curve caches keyed without string building; /xui perf splits cost (rules / visuals / bars / per-frame effects), names the 5 costliest rules, counts which duration path each display took, prints the game's per-addon CPU meter, and saves each report to CueRulesDB.perfLog.
Not done: engine-owned display for this group (needs the group switched on and the automatic facilitator), rule drag-and-drop (#299), stack gating (#300).
