## Decisions used
- **D1** (Xaya): an absent buff has no time left; any time condition on it is NOT met.
- **D2** (Xaya): the game-played aura sound (AddAuraSound) is allowed, opt-in, on its own channel (default Ambience).
- **Fail safe** (VERIFICATION V2): where a signal's meaning is undocumented, it is reported or learned first, never used to decide.

## Scope (V4): what reads aura state, and what changed
- **One presence reading** (`ns.AuraPresence`, Conditions.lua): used by the built-in Buff / Aura (`ns.BuffPresentAny`) and every
  Buff / Aura (another) row (`ReadRowAura`). Target Debuff keeps its own reader and now asks the Cooldown Manager read-only
  (`ns.CDMFrameState`).
- **Readers of a spell ID that a talent can replace** (`ns.SpellOnBar`): charges, cooldown read, `n:cdRemain`, Spell Usable,
  Spell Cast Succeeded (the cast log also stores the base spell).
- **Engine** (Combat/AuraDisplay.lua): row slots, the performance guard.
- Left alone: the debuff reader's own fallbacks (#23); "Show while the aura is up" displays and load (gap 16: Xaya's decision);
  gap 13 (one unreadable extra ID keeps "missing" unknown: changing it risks a false "missing").

## Engine sanity check
- **Performance guard read a dead name.** It summed `XayaUI_CombatEngine` (no such addon since 0.6.0, so always nothing) and
  `Blizzard_AuraContainer`. That container code also draws Blizzard's own target-frame auras (`TargetFrame.xml:324` uses the
  AuraContainer widget), so the reading is not XayaUI's alone, and a trip used to switch the engine off **for good** (saved).
  Now: the guard reads `Blizzard_AuraContainer` only; XayaUI's own total is shown, never used to trip; trips last one session;
  a trip saved by an older version is undone once and reported in `/xuiengine`. The old test stubbed the dead name, so it passed
  (the retrospective's "test mirrors the code, not the game" pattern).
- **Generator bug, no effect on this build:** `build_procs.py` counted an aura with two overlay rows as two auras, and one row's
  buttons overwrote the other's. Fixed; regenerating gave the same files for 12.1.5.70783.

## API reference: secret-aspect names (dev tool)
`docs/reference/build_reference.py` loaded Blizzard's documentation with a stand-in `Enum` that answered 0 for every value, so
`docs/reference/api/widgets.md` printed `SecretReturnsForAspect=[0]` where Blizzard names the aspect. A named Enum value is now a
marker that keeps its name (also through arithmetic: `PlayerCurrencyFlagsDbFlags.InBackpack + PlayerCurrencyFlagsDbFlags.UnusedInUI`).
- **Check:** the old script rebuilt `docs/reference/api` byte for byte from the same inputs (capture of 2026-11-03 21:49, documentation
  12.1.5.70688);
- **After the fix:** the same inputs give the same files with names in place of 0 (aspects, forbidden aspects, enum-valued constants),
  and all 622 documentation files still load. `spells/` is unchanged.

## Inferences (marked; checked in game by QA B33-B40 and the GameDump probe)
- That `AddAuraSound` plays for ordinary auras (Blizzard maps the old private-aura call onto it; no Blizzard UI code calls it).
- That a /reload clears the game's aura-sound registrations (QA B33 checks for a doubled sound).
- That glow events and `IsSpellOverlayed` answer in combat (no secrecy flag in the 12.1.5 docs).
- Which buttons an aura lights (community reading of SpellActivationOverlay's class masks): this is why pairings must be seen in game.
- That the addon profiler counts the containers' work under Blizzard_AuraContainer.
