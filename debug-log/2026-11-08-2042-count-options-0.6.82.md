# Count options drawn again (Rules Options 0.6.82)

Session 014bN6tUDLJ6T742DewZDg1s, branch `claude/keen-pascal-60os7w`. Her words (REQUEST-LOG session 014bN6tUDLJ6T742DewZDg1s #26):

- Cause (reproduced in the stand-in; diagnosis checked by a second reader): Editor.lua set the "Count of" list's `sorting` to a
  closure reading `cntArgs.source`, and `ns.GateRest` then moved `source` into the "Count options" pane (`cntArgs.source = nil`).
  When the section was opened with Show a count ticked, AceConfigDialog called `sorting` (AceConfigDialog-3.0.lua:215, not through
  safecall): "Editor.lua:1624: attempt to index field 'source' (a nil value)". The error stopped the feed: the Count options body had
  no widgets, and nothing after it was drawn (Shield / Absorb Amount, Position, Color & Transparency, Animation Options). Heights,
  fold state and Skin.lua's relays were not at fault.
- Fix: the option is kept in a local before GateRest moves it (one closure). Scope (V4): grep for closures in XayaUI_Rules_Options
  reading a key that GatedPane / GateRest moves found only this one; the group's Display tab "Count of" (DisplayTab.lua) has no such
  override. The same closure served icon, texture, bar and text cues and the Actions banner.
