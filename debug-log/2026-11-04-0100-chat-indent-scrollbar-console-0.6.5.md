# Xaya: chat still has indentation issues and failed wrapping; add a slow-scroll bar; history should show console lines; chat probe error (XayaUI_Chat 0.6.4 -> 0.6.5, fork: main)
Logged 2026-11-04 UTC. GitHub issues: #346 (left indent), the 0.5.107 wrapping report. Four screenshots from Xaya in this session.

Evidence (from her screenshots):
- `/xui chat wrap`: window width 426.0, text area 426.0, line width 426.0 (13 lines), scale 0.7. The window lays its lines out at its real width, so the 0.5.107 "stale width" hypothesis is NOT the cause (ruled out by measurement).
- "widest text 5567.7" in that output is GetStringWidth, the text's width as ONE line. It says nothing about wrapping; the 0.5.107 report was misleading. Replaced by GetWrappedWidth (widest line after wrapping) and a count of lines wider than their box.
- In the wrap output and the /xui help output, the wrapped lines start flush with "XayaUI:". The game's chat turns on a hanging indent for these lines (Blizzard_ChatFrameBase/Mainline/ChatFrameOverrides.lua: self:SetIndentedWordWrap(true), live wow-ui-source, read this session). So the indent is missing (observed). Why: the Chat Panel sets the chat font; FontableFrameMixin:SetFont makes the window a font object of its own (MakeFontObjectCustom: CreateFont + CopyFontObject). Whether CopyFontObject carries the indent is not documented (inference, not confirmed).
- No 40 px gap at the left in these screenshots (text starts at the tab row's left), so #346's original gap was not reproduced this time.
- `/xui chatprobe` failed: Probe.lua:229 compared a secret boolean (IsShown) in tainted code.

Changes (XayaUI_Chat 0.6.5):
1. Indent wrapped lines: a setting (Layout, on by default like the game). C.SetWrapIndent sets it after every font change, only when it differs (each set lays the lines out again), through SetIndentedWordWrap, a ScrollingMessageFrameSecureMixin method (secure even when an addon calls it). Turning the Chat Panel off restores the game's own value. /xui chat indent and /xui chat wrap print the setting, the window's font value and the first line's value.
2. C.Rewrap no longer calls RefreshIfNecessary. That method is not in the secure mixin, so the game's layout code ran as XayaUI_Chat code. Only MarkLayoutDirty (secure) is called now; the window lays its lines out in its own OnUpdate. Taint risk removed; no error from it was seen in game.
3. Chat Panel scroll bar (new Scroll.lua, on by default): right of the text, inside the pane. Arrow click = 1 line (ScrollByAmount); held = repeats after 0.35 s at scrollSpeed lines/s (default 6); thumb drag (SetScrollOffset); track click = one page (PageUp / PageDown); mouse wheel = 1 line. Only secure-mixin methods move the text. It scrolls the selected docked tab. Blizzard's scroll bar is hidden while it is on.
4. History Console tab: print() output (post-hook on the global print, so the game prints first) and CHAT_MSG_SYSTEM go into a separate list shown only under Console, not under All. Protected values are listed as "[protected message]". Not seen: lines an addon writes with AddMessage directly, and print calls through a print saved in a local before XayaUI_Chat loaded.
5. Probe.lua: shown, rel, the region type and the region text are checked with issecretvalue before any comparison.

Verified offline: tests/chat_run.py (new: indent set after font change / set only when different / off / restore / ChatFrame2; wrap report uses wrapped width and counts overflow; Rewrap secure-only; scroll bar placement, 1-line click, no repeat after release, delay then ~6 lines/s, down arrow, wheel, secure methods only, thumb at bottom / top / size / full when nothing to scroll, off gives the space back; Console keeps print + system + protected, strips colors, kept out of All, setting off, tab button). That failure is the same on the untouched code (checked with the changes stashed), so it is not from this change.
