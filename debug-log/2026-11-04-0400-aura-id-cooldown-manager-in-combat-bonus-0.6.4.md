Neither tooltip shows the formula lines, which appear only out of combat: both were almost certainly hovered IN COMBAT (training dummy).
What went wrong in 0.6.1 (my error): the fix relied on GetPlayerAuraBySpellID / GetAuraDataBySpellName, and Blizzard's 12.1.5 documentation marks GetPlayerAuraBySpellID SecretWhenUnitAuraRestricted and RequiresNonSecretAura (Blizzard_APIDocumentationGenerated/UnitAuraDocumentation.lua). In combat they give no answer, and AuraModel learns casts only out of combat. The stub tests assumed the call answers; they did not model the combat rule. Demon Spikes was never covered: its buff (203819 per Options.lua, not independently confirmed) has a different ID, and the only sources for that case were the same ones. I reported the 0.6.1 fix without saying either limit.
Source added: C_CooldownViewer (GetCooldownViewerCategorySet(category, true) + GetCooldownViewerCooldownInfo); its documentation lists no secret returns, so it reads in combat. Readings used, both from Blizzard's own Cooldown Manager code (Blizzard_CooldownViewer/CooldownViewerItemData.lua, wow-ui-source live 12.1.5): linkedSpellIDs are aura IDs (FindLinkedSpellForCurrentAuras looks them up with C_UnitAuras.GetUnitAuraBySpellID); a TrackedBuff / TrackedBar entry with no linked IDs and no overrides can only match an aura with its own spellID (GetAssociatedAuraSpellPriority). hasAura and selfAura are not used (Blizzard's code never reads them; undocumented). An override spell gets the same linked auras. Empty answers (data not loaded at login) are not cached; the map is reset on spec / talent changes and COOLDOWN_VIEWER_DATA_LOADED / _TABLE_HOTFIXED.
Also: in combat, an unknown aura now says "not known yet (auras are hidden in combat)". New /xuitt aura [spellID]: loaded Bonus version, combat state, Cooldown Manager links, live aura read, recorded casts, and what the tooltip shows.
