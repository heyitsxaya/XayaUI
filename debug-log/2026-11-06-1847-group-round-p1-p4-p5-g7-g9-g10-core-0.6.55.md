## What was built
- **P1 (#268):**
  - `visual.point` is the display's own point. `ns.SetVisualPoints` changes either point and keeps the display in place.
  - Position section: "Anchor point", then "Anchored to:" (the group, the screen or the snapped frame), then "To <target>'s point".
  - **Bug found and fixed:** Visual.lua had a second, sides-only `OPP` table that hid the full one. As a result, "Outside" with a
    corner anchor silently acted as "Inside" (the display was 40 px off, measured in the test).
- **P4:** the arrow keys nudge the display or group last clicked or dragged in the mover view: 1 px per press, Shift 10 px. The key
  frame is made on the first unlock (V14). Every other key reaches the game. Nothing happens in combat.
  - INFERENCE: whether `SetPropagateKeyboardInput` is restricted in combat is not in the API index. The call is guarded with
    `InCombatLockdown`.
- **P5:** the mover session.
  - When the view opens, the draft is taken (`CueRulesDB.moverDraft`).
  - Leaving the view after a move asks Save moves / Cancel moves. Escape does not close the question.
  - The lock icon on a group tag locks that group for now: no drag, and the mouse passes through to what is underneath. Nothing is
    saved, and the lock ends with the view.
  - A draft left by a /reload or logout is offered back at login.
  - **Limit:** the game writes saved data only at logout, /reload, disconnect or quit, so moves cannot survive a crash. Sources: the
    WoWProgramming forum quoting the WoWWiki page "Saving variables between game sessions"
    (https://wowprogramming.com/forums/development/288.html) and a WoWInterface thread
    (https://www.wowinterface.com/forums/archive/index.php/t-1332.html).
- **G7:** a static group can keep an arrangement (`cArrX` / `cArrY` / `cArrGap`).
  - It is applied again on every refresh, drag and nudge, so a dragged display goes back into line.
  - It covers the group's own displays only, never snapped ones.
  - The arrangement math moved to core (`ns.ArrangeList`).
- **G9:** "Scale items to fit the box" (set size, static groups only).
  - The container is scaled down by the factor the items need and enlarged by the same factor, so the box keeps its size on screen.
  - Making the box too small with the tick box off asks "Scale the items to fit?" once.
  - INFERENCE: displays anchored to a corner are measured from the centre, so their fit is approximate.
- **G10:**
  - Dynamic groups gain **Limit**: after sorting, only the first N show; the rest wait (hidden, marked `xuiLimited`).
  - They also gain **Align**: Top / Center / Bottom for rows, Left / Center / Right for columns. Unset keeps today's look.
  - Align & Arrange moved to the Group tab.
- **RM-LAYOUTS:** a scaffold on the branch `roadmap-features/layout-profiles` (heyitsxaya/XayaUI#421, #422).
- **Static gate fixes:** the earlier commits failed the suite, and these fixes clear it.
  - The Dev Assist walkthroughs reach the Shopping List through the "shoppingList" service (QoL 0.7.33).
  - They delete their test group through `ns.OptionsApi.DeleteFolderAll`.
  - Their buttons use `ns.FlatButton`.
  - `devassist_rename_run` allows the generated checklist file (step J12 names the old folder).
- `Visual.lua` guards `ns.AtLogin`, because `layout_parity_run` loads it without Modules.lua.
- New hand-written walkthroughs: display-points (B177), mover-session (B178), group-arrange (B179), group-fit (B179b) and
  dynamic-limit-align (B179c).
