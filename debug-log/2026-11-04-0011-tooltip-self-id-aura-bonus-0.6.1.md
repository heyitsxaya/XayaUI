# Tooltip "Aura ID: not known yet" on spells whose buff has the spell's own ID (Bonus 0.6.0 -> 0.6.1, core 0.6.3 -> 0.6.4 after merging main, fork: claude/exciting-hypatia-huaqbv)
Logged 2026-11-04 00:11 UTC. GitHub issue: #281 (aura IDs on spell and item tooltips).
Report (Xaya, two screenshots): Immolation Aura's tooltip shows "Spell ID: 258920", "Icon ID: 1344649", "Aura ID: not known yet" while the spell is recharging (6 of 12 sec) and the fel flames are on her character.
Cause (code reading, not checked in game): every aura source the tooltip uses threw away an aura whose ID equals the spell's ID: TT.AurasFor's add(), the same-name live read (`sid ~= id`), AuraModel.AurasForCast (`aid ~= castID`), and AuraSources.Note. A spell whose buff shares its ID could therefore never get an aura line, and any spell text with "N sec" fell through to "not known yet". Evidence that Immolation Aura is such a spell: XayaUI_Options/Options.lua:2737 lists its buff ID as 258920 ("your debug log"), the same number as the spell ID on the screenshot.
Change: TT.AurasFor returns a second value, `same`. Proof that counts: the aura is on you now (C_UnitAuras.GetPlayerAuraBySpellID(id) returns a readable non-nil answer, or the same-name read returns the spell's own ID); a cast of the spell was seen to apply it (new core reader AuraModel.CastAppliesSelf; the recorder already stored this case, only the reader dropped it); or one of those was seen before in this game build (CueRulesDB.tooltips.selfAura = { build, ids }). The line reads "Aura ID: 258920  (same as the spell)" and replaces "not known yet". A tooltip's embedded effect block pointing at the spell's own ID is NOT counted (it can describe damage, not a buff); that existing test is unchanged. Items never get this line.
Not changed: AuraModel.AurasForCast, AuraSources.Note and the rule editor's search "source" column keep leaving out the self case (a spell listed as its own source adds nothing there).
Checks: tests/tooltips_run.py 45/45 (10 new; corrected 2026-11-04: first written as 47/47, a miscount: live buff, remembered after it ends, saved data, a different duration spell still "not known yet", recorded cast, same-name read, secret answer is not proof, throwing API contained, Aura IDs option off, items). Negative control: with the old Tooltips.lua the new checks fail. All 23 tests/*_run.py pass. Whole-addon harness: fails on Options.lua:4596 (`C_Texture` is nil in the harness); the same failure occurs on the untouched branch head, so it predates this change.
Unverified in game: whether GetPlayerAuraBySpellID / GetAuraDataBySpellName answer readably IN combat in 12.1.5 (her screenshot is on a training dummy, likely in combat). If they come back secret, the line appears after one cast out of combat instead.
Also seen on the screenshot, not changed: the spell and icon IDs appear three times. Two of the sets ("SpellID / IconID" without a colon, and a single yellow "SpellID: 258920") are not XayaUI's format; another installed addon adds them. Needs Xaya's call (see the session reply).
