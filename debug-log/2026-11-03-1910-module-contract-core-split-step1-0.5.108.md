# Xaya: split XayaUI into separate addons; step 1 prepares core (XayaUI 0.5.108, fork: main)
Logged 2026-11-03 ~19:10 UTC (time corrected in 0.6.0; it first said ~20:00). Architecture request: XayaUI becomes separately switchable addons: XUI core (rules, combat aura tracking), XUI Chat (all chat changes), XUI QoL (cursor; friends and bags later), XUI Bonus Features (enhanced tooltips, notepad, custom data panels), XUI Blizzard Reskin (restyles Blizzard frames without changing what they do), XUI Options (the settings window as its own load-on-demand folder). Decided in chat: minimap button and ESC-menu button stay in core; theme, console and debugging, aura source lookup, and the rule / theme sharing codec stay in core (the import window goes to Options); XayaUI_Media is a support folder for core, not a feature; Data Blocks becomes a shared library carried by Chat and Bonus (not core).

Step 1 (this build) changes no behavior. Everything still loads from the XayaUI folder; the files only stop being called by name:
- New Modules.lua (loads right after Core.lua): the contract between core and features. ns.WhenReady (start once the saved settings exist; immediately for an addon that loads later), ns.RegisterCommand (/xui commands; several handlers per name allowed), ns.RegisterLauncher (minimap list rows), ns.RegisterSettingsPage (settings pages, grouped by module), ns.MODULES (which addon owns which command, so /xui <cmd> can say "switched off" or "not installed" instead of doing nothing). Every registered function runs in pcall: one feature's error no longer stops the next feature from starting (before, Core.lua called the start functions in a row, unprotected).
- Core.lua: no feature names left. Startup = engine first, then ns.FireReady(); the chat, privacy, chatprobe, data, notes, panel, cursor, and gamemenu branches of /xui moved into their own files; help text = core commands + what features registered.
- Features register themselves: Chat/Core.lua, Chat/Options.lua, Chat/Probe.lua, ChatPrivacy.lua, DataPanels.lua, Notepad.lua, CursorTrail.lua, TooltipsUI.lua, GameMenu.lua, GameMenuSkin.lua, MinimapButton.lua. Shelved QoL.lua and CursorTracker.lua (not loaded) are wired the same way for when they come back.
- Minimap button: rows come from the features. A row with no saved choice is shown; saved true / false choices are kept as they are.
- Options.lua: the QoL UI Updates tree is built from the registered pages (same pages, same alphabetical order).
- AuraSources.lua: the embedded-aura reader (AS.EmbeddedAuras, AS.NestedType, AS.SpellType) moved here from Tooltips.lua so core never depends on the tooltip feature; TT.EmbeddedAuras stays as a forwarder.
Verified offline: tests/modules_run.py 22/22 (new); all 19 existing runners pass (chat_world.lua, chatprobe, gamemenu, minimap, notepad, tooltips updated to load Modules.lua; tooltips keeps only the reader from AuraSources so it still tests Tooltips alone); every Lua file in the toc compiles.
Unverified in game: load order of the registrations, the minimap list, /xui help text, and the settings tree after /reload.
Next steps: Blizzard Reskin, QoL, Bonus, Chat as their own folders; Data Blocks as a LibStub library; per-kind share handlers (rules, themes) on one core codec with a newer-version message, a never-export field list, and combat deferral; Options as a load-on-demand folder last.
