# Xaya: notepad undo, spell token entry, tooltip aura name + ID (XayaUI 0.5.101, fork: main)
Logged 2026-11-03 ~05:00 UTC. GitHub issues: #281 (tooltip aura, comment), #254 (notepad, comment). Reported against build 0.5.100 (notepad and tooltip code last changed before 0.5.99).

1. "allow for ctrl z functionality in the notepad". The typing box (a Blizzard EditBox) has no undo. Added per-note undo and redo: Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z. Quick typing is one step; a pause or a paste or delete of 20+ characters is its own step; Clear and restoring an earlier version are steps too. Session only, 200 steps per note. Tests: tests/notepad_run.py (10 new checks, all pass). NOT verified in game: that the game delivers OnKeyDown with key "Z"/"Y" to a focused EditBox while Ctrl is held, and SetText/SetCursorPosition behaving as in the stub.
2. "entering a spell doesn't update the spell format properly" (screenshot: note with an empty {spell:}). I could not reproduce what she typed, so this is an INFERENCE: the token only accepted digits, so a spell name, a pasted spell link, or a space inside the braces stayed raw. Now {spell:...} takes an ID, a name, or a spell link, trims spaces, and an unknown token stays visible in grey. The Spell button tooltip says so. NotepadShare (chat and titles) uses the same resolver. Open question for Xaya: what exactly did she type, and what did she expect the box to show? (If she expects the icon and name to appear while typing, that needs the formatted view: an EditBox cannot show icons.)
3. "tooltip option when hovering an item or spell should show both the item/spell ID AND its corresponding aura name + id" (screenshot: Darkness 196718, no aura line; the extra SpellID / IconID / "SpellID:" lines in the screenshot come from other addons, not XayaUI). Cause: the Aura ID line only used the tooltip's embedded effect block, which Darkness does not have. Now also from: effects remembered from earlier tooltips (AuraSources), auras this character's casts were seen to apply out of combat (AuraModel.AurasForCast, new), and for spells a buff on you with the same name (remembered). Otherwise, a spell whose text names a duration shows a grey "Aura ID: not known yet" (option). No data is shipped and nothing is guessed, so Darkness shows 209426 only after it is learned (cast once out of combat, or hover while the buff is on you). Tests: tests/tooltips_run.py (11 new checks).
