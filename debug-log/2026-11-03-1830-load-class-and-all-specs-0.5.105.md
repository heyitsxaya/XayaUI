# Tester + Xaya: load conditions must cover any class and spec from any character (XayaUI 0.5.105 / engine 0.4.4, fork: main)
Logged 2026-11-03 ~18:30 UTC. GitHub issue: #319. Tester Insivius (via Xaya): other classes / specs do not populate on the Load tab, so auras not listed as spec specific for his Death Knight load on his Paladin, and he cannot set them to "Death Knight" only. Xaya: "you should be able to assign load conditions for other classes while on a different class" and "you should also always be able to assign any spec / class from any character regardless of the match".
Cause (read from the code): no Class load condition existed; the Specialization list was built from the logged-in character's own specs; the spec boxes were single choice.
Change: new Class condition (rule.load.classes, classUse; 13 classes, always all listed, multi-select) on the rule Load tab and on a group's Load tab (loadClasses, checked before the rule's own); Specialization lists every specialization of every class (class and spec in the label, all listed whatever you play, multi-select; falls back to the character's own specs only if the game gives no class list); context carries the class (ctx.class, part of the load memo key); the combat engine's lean mode skips rules for other classes. Existing rules and exports are unchanged (a missing class field means any class).
Also found while building: Options.lua sat at the game's limit of 200 file-level local variables, so the new helpers live in one block with a forward-declared local (net zero new locals); checked with a compile test.
Verified offline: tests/load_class_run.py 21/21 (rule and group class gates, Always / ANY / switched-off behavior, class change follows the memo, lists complete while on a Paladin, fallback), plus timing, aura_display, layout_parity, import, export_group, drafts, class_learn, perf suites, and a compile check of Options.lua, Conditions.lua, AuraDisplay.lua.
Unverified in game: how the Class and Specialization boxes render and click in the options window; the class and spec names and icons from the game's class API (GetClassInfo, GetSpecializationInfoForClassID); the Hero Talents list still shows only the logged-in character's class (the game's hero-tree call needs that class's talent data; left as it was).
Files: Options.lua, Conditions.lua, XayaUI_CombatEngine/AuraDisplay.lua, USER-GUIDE.md, XayaUI.toc, XayaUI_CombatEngine/XayaUI_CombatEngine.toc, MANIFEST.md5, tests/load_class_run.py.
