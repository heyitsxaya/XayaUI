AceGUI pooling cluster

One root cause, confirmed against the vendored Ace3 source: AceGUI's pool is shared by every Ace3 addon in the client, and Release clears only userdata, events, size and points. Hooks and fields XayaUI leaves on pooled widgets therefore reach other addons' windows. One fix pattern covers all five: undo each patch on release with the existing AddRest / OnRelease helpers (HookScript handlers cannot be removed, so give them a flag the restore clears), or gate on AceConfigDialog.OpenFrames[APP]. None of these is filed.

  1. MediumCorrectness

    Downgraded from highRelated: #266 (undo lost on close)
    XayaUI_Options/Options.lua:1198-1205

    Return at the top of the hook unless OpenFrames[APP].frame == self, or move DraftsOnClose and SearchOnClose inside Tree.Closed after its guard. Do not nil-check OpenFrames[APP]: on a genuine close it is already cleared before the hook runs.

    Verifier: needs two Ace windows open in order; the edits land in Drafts with a notice and the window state recovers on the next redraw.

  2. MediumCorrectness

    Confirmed, worseNew
    XayaUI_Rules_Options/SpellSearch.lua:537-561

    Add an OnRelease wrapper on the EditBox widget that clears xuiSearchFn and xuiSearchKind (the Skin.lua AddRest helper is local, so SpellSearch needs its own or an exported one).

    Verifier: focusing a stale box also starts XayaUI's whole-game index scans inside the other addon's window.

  3. MediumCorrectness

    Confirmed, worseNew
    XayaUI_Options/TreePaint.lua:476-486 · Skin.lua:965-1031, 2337-2407 · Options.lua:1502-1550

    Restore method wrappers with AddRest (methods are instance fields, so the original can be put back); give HookScript handlers a flag the restore clears.

    Verifier: the dropdown pullout is its own pooled widget shared by every Ace3 dropdown, so the width wrapper and backdrop reach unrelated addons; the row hooks give other trees XayaUI's right-click menu, multi-select and drag.

  4. MediumEfficiency

    ConfirmedNew
    XayaUI_Options/Skin.lua:1784-1831

    Keep the arrows on the frame, hide them on release, and on acquire show them, re-anchor, and re-register the AddRest restore (cleared on every release). Re-pointing step is unnecessary.

    Verifier: the leaked buttons are also walked by every decorate pass, so passes slow down as they pile up.

  5. LowCorrectness

    DowngradedRelated: #231 added the menu
    XayaUI_Rules_Options/Sidebar.lua:1338-1373

    In the hook, return unless self.obj is the tree inside OpenFrames[APP].frame. Also undo EnableMouse(true) on release.
