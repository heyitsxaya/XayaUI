## 2. Comparison table

Columns: **EUI / ElvUI / XayaUI** = whether that addon offers the concept and where. "Fixed behaviour" means the addon does it on
its own with no setting; "editable macro text" means ElvUI ships a default show/hide string the user may edit, not a dedicated
setting. XayaUI's side was read from `XayaUI_Rules/Conditions.lua` (`ns.LOAD_TRI` line 1684, `ns.INSTANCE_TYPES` line 1704,
`ns.ReadContext` and its change signature around lines 1855-1885, the ID-list table `ID_LISTS` lines 1890-1894, `IdListWalk`
line 1898, `CheckContextRaw` line 1962, the group overrides inside it, and `rule.talents` from line 1571), `XayaUI_Rules/Editor/Editor.lua`
(the Load tab's ID-list fields, around lines 440-460, and its add-current button at line 504), `XayaUI_Rules/Triggers.lua` (the Player State trigger, lines 113-117 and
877-900) and `XayaUI_Rules/Engine.lua` (the load-context event list `CTX_EVENTS`, lines 1409-1416, handled at about 1593-1601).
"Trigger only" means XayaUI can already test it inside a rule's trigger, but not on the Load tab.

**How a new load fact reaches the gate (applies to every item in 2b).** The engine re-reads the load context only for events in
`CTX_EVENTS` (Engine.lua:1409-1416). Events registered elsewhere (the bar events at Engine.lua:1423, PLAYER_TARGET_CHANGED at
:1427) re-check loaded rules but do **not** re-read the load context. And a re-read only counts as a change if the new fact is part
of `ReadContext`'s signature (Conditions.lua:1876-1883); otherwise the memo at Engine.lua:1599-1600 sees nothing new. So each new
row needs (a) its events in `CTX_EVENTS` (unit events registered for "player" or "target" the way UNIT_FLAGS is at :1424-1425),
and (b) its value in the signature. The event plans below say which events are new to `CTX_EVENTS`.

API column: entries in `docs/reference/api/` are cited as file:line. "undocumented" = the name exists in the client but has no
signature in the generated docs; "not in the reference" = no entry at all (INFERENCE that it behaves as the reference addons use it).

  appear inside an element, not when the element loads. Checked and out of scope.

## 4. Independence statement

Nothing was copied from EllesmereUI or ElvUI: no code, no data, no option keys, no setting identifiers, no feature names, no label,
tooltip or locale text, no assets. Each concept above is described in our own words from the behaviour it produces, with the
source cited as file:line. An independent check found some wording in the first draft that echoed the reference addons' own
names (their feature names, mode names and some option labels); all of it was replaced with our own descriptions in this
revision. A second check round found more phrases that still followed reference labels or tooltips closely (for example
the garrison, travel-shape, skyriding, target, level and vehicle wording); those were reworded as well. Blizzard API, event and game-feature names (such as Quick Keybind mode, War Mode) are the game's and are named as such.
Their files were read as text only, never run, and kept in their own scratchpad directories. Her Drive folder was only listed and
size-checked; nothing in it was written, moved, renamed or deleted. Any XayaUI implementation of these concepts will be our own
design and our own code, built on the game API entries cited from `docs/reference/api/`.
