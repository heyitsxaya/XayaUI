# XayaUI toggle audit (read-only)

Date 2026-11-08. Repo HEAD d3b5cc8; another worker was editing files during this audit (by the end: XayaUI/Core.lua, DebugRecord.lua, Modules.lua, XayaUI_QoL/CharacterReskin.lua, XayaUI_Reskin/*, many tests). The dump comes from a snapshot taken early on, so line numbers in those files may move. Nothing in the repo was written.

## Method (facts)

- Source of truth: the whole options tree as built by the real addons in the test harness. `tests/options_split_parity_run.py --dump` was run on a copy of the working tree in the scratchpad (it writes only to the dump dir, `tests/options_split_parity_run.py:188-203`); a second read-only run with the same harness added each control's get() result, the xuiSwitch get/disabled/hidden results and the Lua source of each get/set (debug.getinfo). Dumps: `/tmp/claude-0/-home-user-XayaUI/dd00f6e3-e5ad-57cb-a3a4-bd0bd8ea09f1/scratchpad/dump/all-on.txt`, `/tmp/claude-0/-home-user-XayaUI/dd00f6e3-e5ad-57cb-a3a4-bd0bd8ea09f1/scratchpad/full.txt`. Saved variables empty, so get() = shipped default.
- Every module on. QoL Elements (stat boxes, cursor tracker, buff bars) are shelved and not in the window (`XayaUI_Options/Options.lua:1011`). XayaUI_Media registers no settings page.
- **Clicks** = navigation clicks needed before the control is on screen, NOT counting the click on the control itself, from the first open in a session. Rules used, each from code:
  - The first open of a session lands on the Rules tab (`XayaUI_Options/Options.lua:1157-1165`), so every other top tab costs 1 click.
  - A tree selects its first row when nothing is selected, a tab group its first tab (`XayaUI_Options/Libs/AceConfig-3.0/AceConfigDialog-3.0/AceConfigDialog-3.0.lua:1688-1693, 1748-1753`); those cost 0.
  - A feature page with parts in the left pane starts expanded in feature tabs (QoL, Bonus Features, Blizzard Reskin) (`XayaUI_Options/Options.lua:47-60, 214-222`), so a level-2 row costs 1 click (select) and no expand click.
  - An xuiSwitch is a tick box on the row itself (`XayaUI_Options/TreePaint.lua:211-255, 304-334`), so it costs only the top tab (1) when its row is visible.
  - After the first open the window remembers the last tab/row/sub-tab within the session (AceConfigDialog status tables), so later opens can be fewer or more clicks.
- **Hidden / greyed at defaults**: some controls are not visible until a parent switch is on (e.g. Data Panels' sub-tab, Character Toolkit parts, the stat-list page) or are greyed while their feature is off (`XayaUI_Options/Options.lua:236-290`). Getting to them costs one extra click (the parent switch); noted in the Notes column, not in Clicks.
- In scope: on/off controls whose effect shows, hides or enables a feature, element or visible part, plus every xuiSwitch. Left out: pure style (border, background, bold, tile, colours, 24h clock, labels), conditions (hide in combat, only on mouseover, only in dungeons, hide while mouselook), Profiles import/export part pickers, Dev Assist record categories, Settings-window-only display preferences, and every per-rule toggle in the Rules tab (rule Enabled, load conditions, Auto-Generate picks: these are rule content, not addon features). Sets of identical per-item boxes (per window, per slot, per stat, per chat tab) are one row with their count.
- "Label as shown" for an xuiSwitch: the box has no text; its row name is the visible label, and the hover tooltip shows the row name (falling back to the switch name only if the row has none), one sentence and Enabled/Disabled (`XayaUI_Options/TreePaint.lua:286-299`). The switch's own `name` is therefore not shown to the player.
- Column "Label says what it turns off?" is a judgement (INFERENCE) of whether the visible label, read alone, names the thing switched.
